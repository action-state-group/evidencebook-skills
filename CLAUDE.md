## Local check

Before every push: `scripts/check.sh` (its jobs run at once, so it takes about as long as its slowest job; needs git, gh signed in, Go, uv, python3, bash 4.4 or later and Google Chrome, and fetches its pinned checkouts and released binaries into `~/.cache/evidencebook-skills-check`). It runs every job of `fast.yml` with CI's commands, the checks of `contracts.yml` and `neutrality.yml` (the scan only when the term list is at `$NEUTRALITY_TERMS_FILE`, default `~/.config/evidencebook-skills/neutrality-terms.json`; otherwise its last line says NOT RUN), and the unit tests of `tests.yml`'s two jobs (`ard-demo-unit`, `tau2-live-unit`). The end-to-end runs of those jobs, `ard-demo` and `tau2-live`, take several minutes each and run only with `scripts/check.sh --full`; run it when a change touches a demo, or leave it to `tests.yml` on main and nightly (#425). `scripts/check.sh --plan` prints the selection and runs nothing. Each job runs without your shell's `ARD_*` variables and with fresh, empty demo folders of its own (`ARD_HOME` and the rest), so your seeded `~/.config/ard-commerce-demo` never changes a result, and the demo's tests fail any test that reaches it (#357). No job binds a fixed port (ard-demo picks a free stage port, and its witness, local since #371, a free one too) and runs at the same time share the dependency cache under a lock, so the check needs no e2e lock: `asg-local-check --heavy scripts/check.sh`.

Pull requests run only the fast set (`fast.yml`); `ard-demo` and `tau2-live` run nightly and on main (`tests.yml`). To run them on a branch's CI, dispatch `heavy tests` on it: `gh workflow run tests.yml --ref BRANCH`.
